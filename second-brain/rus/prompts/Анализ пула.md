Ты анализируешь пул аспектов одного контейнера (проекта) в личной системе заметок. Аспект — атомарная смысловая единица, извлечённая из записи автора. Твоя задача — найти связи между аспектами: что складывается в одно целое, что повторяется, что устарело, что противоречит друг другу, и не пора ли менять структуру.

## Что найти

1. Составные аспекты. Собирай по формулам, только если аспекты действительно про одно и то же событие, вопрос или решение. Например, resolved_decision: вопрос «чем мерить пульс на бегу», две гипотезы и вывод «берём нагрудный датчик, потому что…». Сначала попробуй достроить существующий составной той же формулы (extend), потом собирай новый из свободных аспектов. Аспект может входить только в один составной. Не притягивай: случайный набор аспектов нужных типов — ещё не составной. Для составного напиши text: одно-три предложения, описывающих целое. Составной со status needs_review пересобери (extend с новым набором) или распусти (dissolve).
2. Дубли. Аспекты, которые говорят одно и то же разными словами и не противоречат друг другу. Укажи пару: aspect и duplicate_of. Какой из них главный, программа решит сама по дате.
3. Устаревание. Более новый аспект опровергает или пересматривает более старый по тому же вопросу: пересчитанная сумма, изменённое решение, проверенная и отброшенная гипотеза. Укажи aspect (старый) и replaced_by (новый), с уверенностью 0–100. Если оба утверждения могут быть верны одновременно, это не устаревание.
4. Противоречия. Два актуальных аспекта одного типа, которые не могут быть верны оба и при этом ни один не пересматривает другой по времени. Например, две идеи, исключающие друг друга. Сравнивай только аспекты одного типа. Дай предполагаемое решение: assumed — "a" (вероятнее, что автор держится первого), "b" (второго) или "both" (это законная развилка, оба направления живы), и коротко поясни в assumption.
5. Структура.
   - seed_to_project — только если контейнер сейчас seed, а материал уже показывает цель, планы и развитие.
   - subcontainer — если внутри контейнера сложилась отдельная подтема с собственным развитием (обычно от трёх записей). Укажи название, тип, описание и id записей, которые туда перейдут.
   Для каждого предложения дай уверенность 0–100.

Если ничего не нашёл в каком-то пункте, верни пустой список. Не придумывай связи, чтобы заполнить ответ.

## Формат ответа

Только JSON, без пояснений вокруг и без обёртки в блок кода. В каждом объекте поле reasoning пиши первым, коротко, на языке аспектов.

{
  "reasoning": "общая картина пула",
  "composites": [
    {"reasoning": "…", "extend": null, "composite_type": "resolved_decision", "from": ["a3", "a7", "a9"], "text": "…"}
  ],
  "dissolve": [{"reasoning": "…", "composite": "c2"}],
  "duplicates": [{"aspect": "a12", "duplicate_of": "a4"}],
  "outdated": [{"reasoning": "…", "aspect": "a5", "replaced_by": "a14", "confidence": 85}],
  "conflicts": [{"reasoning": "…", "a": "a6", "b": "a11", "assumed": "b", "assumption": "…"}],
  "structure": [
    {"reasoning": "…", "kind": "subcontainer", "title": "…", "type": "project", "description": "…", "entities": ["e00012", "e00015"], "confidence": 80}
  ]
}

Правила полей:
- extend — id существующего составного, который достраивается (тогда from — полный новый состав), или null для нового.
- Все id — только из переданных списков.
